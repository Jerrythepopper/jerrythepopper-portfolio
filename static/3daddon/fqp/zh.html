Final Quality Pipeline 使用手冊

版本 1.3.0 ｜ 適用 Blender 5.1 / 5.2 ｜ 只支援 Cycles ｜ 網頁版（有截圖）：jerrythepopper.com/3daddon/fqp/zh.html

一條給 Cycles 用的出片級降噪管線。它把畫面拆成各路光線成分，每一路光先乘上材質顏色再分開、全程 HDR 不壓縮地降噪，並以 albedo／normal 引導，最後給你每一路一支滑桿——微細節要留多少，由你決定。動畫另外多一層跨幀處理，消掉降噪造成的閃爍，並在最後把動態模糊補回來。

另外附兩把量尺：一把算出這個場景實際需要幾次光線反彈，一把算出雜訊門檻要收到多緊——後者跟「每一幀要花幾秒」根本是同一個問題。

1. 安裝

這個 .zip 會裝成 extension。入口有兩個，結果一樣。

  • 把 .zip 直接拖進 Blender 視窗；或到 Edit > Preferences > Get Extensions，右上角的下拉選單選 Install from Disk。
  • 或到 Edit > Preferences > Add-ons，右上角的下拉選單選 Install from Disk，選那個 .zip。

只留一份就好——多出來的一份（例如以前留在 scripts/addons 資料夾的舊版）會搶同一個面板。它在外掛清單裡叫 Who Needs Another Render Setup? (Final Quality Pipeline)，搜哪個名字都找得到。面板本身的標題還是 Final Quality Pipeline，出現在 Properties > Render 的最上方，就在算圖引擎選單正下方。

需求：Blender 5.1 或 5.2，算圖引擎必須是 Cycles。這不是偏好問題——整條管線吃的是只有 Cycles 生得出來的 per-pass 與 denoising 資料，EEVEE 給不出來。

2. 語言

這個外掛講英文和繁體中文，而且切換鈕是它自己的：面板最上方那一排（或 Edit > Preferences > Add-ons 裡這個外掛自己的偏好設定）有三個選項。

設定意思
自動跟著 Blender 畫面上實際顯示的語言走：Blender 介面設成中文，而且 Blender 真的有在翻譯介面（Preferences > Interface > Translation > Interface 打勾）時用中文，其餘用英文
English不管 Blender 設什麼，一律英文——連 Blender 自己有翻譯的字（例如 Diffuse、Shutter）也是英文
中文不管 Blender 設什麼，一律繁體中文

因為它跟 Blender 的介面語言是分開的，你可以讓 Blender 維持英文、這個外掛看中文，反過來也行。選好會記住，換檔案、關掉重開都還在。

「自動」是在你選它的時候、以及 Blender 啟動時做判斷。Blender 開著的時候改了 Blender 的語言或翻譯開關，請把這個外掛的語言重選一次（或重開 Blender），它才會跟上。

切換是當場生效的：面板文字、按鈕名稱、滑鼠停留的說明全部立刻換掉，而且你設過的東西一個都不會動。兩支分析器寫出來的報告、背景算圖視窗裡的進度行，也跟著同一個設定走。

3. 三分鐘速查

出一張靜幀

  1. Properties > Render > Final Quality Pipeline
  2. 按 建立管線
  3. 按 套用出片採樣設定
  4. 按 設成 32-bit EXR 輸出
  5. F12 算圖
  6. 渲完拖 高光 滑桿（0.7～1.0）找質感。它是即時的，不用重渲。預設只作用在畫面很亮的地方（只在高光混回），所以亮度平均的場景拉了可能完全看不出差別，這是正常的。

出一段動畫（含消閃爍）

  1. 上面 1～4 照做，然後存檔
  2. 把 Motion Blur 關掉（Render Properties > Motion Blur）。這不是建議，是必要條件——原因見常見問題。
  3. 按 準備動畫素材輸出，然後照平常渲動畫
  4. 按 建立跨幀場景，再按 執行跨幀穩定
  5. 成品在 //fqp_final/<blend>_<scene>/，檔名是 stabilized####.exr。整段的頭尾幾幀會少，這是故意的：它們有一邊沒有鄰居可以混。

交件前

按一下 健康檢查。它什麼都不會改，只會一行一行告訴你這個場景有沒有踩到九個已知的地雷——另外還有幾行只在用得到時才出現。

4. 它到底在做什麼

Cycles 可以把光線分成好幾份輸出：漫射、高光、穿透、自發光、體積——前三份還再拆成「照到多少光」和「表面本身什麼顏色」。一般的降噪是在完成的畫面上一次做完，那時候各種光早就混在一起了，粗糙金屬、玻璃、霧面材質只能共用同一套處理。

這條管線改成一份一份來：每一路光先乘上材質顏色再降噪，每一份分開處理，全程 HDR、白的地方不切掉；材質紋理與降噪器一起處理，並以 albedo／normal 引導。自發光和體積（Volume Direct/Indirect）沒有自己的顏色 pass，所以直接降噪、直接加回去，不做那一次相乘。

接著每一路各給一支滑桿，在「原圖」和「完全降噪」之間調。降噪器傷得最重的是反射——它會把粗糙金屬的高光燙成塑膠——所以「高光」那一格預設就低於 1。預設只在畫面很亮的地方把原圖混回來（只在高光混回）：高光保留顆粒和層次，其他地方維持乾淨。所以畫面裡沒有很亮的地方時，拉滑桿可能完全看不出差別，這是正常的，不是壞了。想讓滑桿作用在整個畫面（例如要全畫面的顆粒感），就把只在高光混回關掉，再按「重建管線」。體積那支滑桿不受這個開關影響，一律作用在整個畫面。

動畫還有第二段。每一幀各自降噪會讓畫面浮動，因為降噪器每一幀猜的都不太一樣。跨幀那一段會抓每一幀的鄰居，用 Cycles 算出來的運動向量把它們搬到正確位置，把深度對不上的像素（以及緊鄰它們的像素）丟掉，剩下的混起來。這要求 Cycles 自己的動態模糊必須關掉，因為糊掉的畫面生不出能用的運動向量——模糊改在最後一步補回去。鎖定機位或慢速鏡頭效果最好；快速推軌或橫移時，在背景前移動的物體輪廓可能比不開跨幀穩定稍差（見「已知限制」）。

5. 面板逐項說明

主區

項目作用
健康檢查九項檢查，外加幾項只在用得到時才出現。什麼都不改。詳見下一節。
建立管線打開需要的 passes，把節點群組接好，放在你的 Render Layers 節點旁邊。會自動插到你既有濾鏡鏈的最前面，降噪永遠是第一站。其他原本吃算圖原圖的地方——第二條分支、File Output——也一併改吃降噪後的圖；Viewer 節點保持吃原圖。有好幾個 view layer 時，讀的是你目前所在的那一層；那一層不會被渲染（Use for Rendering 沒勾）時，改建在第一個會渲染的 layer 並跳警告，全部都不渲染時什麼都不改、直接說明。有好幾顆 Render Layers 節點時，用的是 Image 接到最終輸出的那一顆；有好幾顆 Group Output 時，用的是作用中那一顆的第一個輸入（Blender 算圖用的就是它）。Compositing 沒開的話會幫你打開。隨時可以再按。
移除先問你一聲，再把群組拿掉、接線還原成你原本的樣子，並關回建立時打開的 passes。建立時對場景做的其他事也一併還原：建立時新建的合成樹會拿掉；建立時補上的 Render Layers／Group Output 節點，之後沒人接線的會刪掉；Compositing 與合成器裝置改回原本的設定——除非建完之後你自己改過。你自己的節點不會被動到。建完之後你自己改過的線，會維持你改的樣子。

漫射（1.0）漫射降噪強度。預設 1（完全降噪）；漫射打光看起來很塑膠、或想在漫射表面留一點顆粒時，再往下拉。
高光（0.85）最先該動的那一支。往下拉可以把高光顆粒放回拉絲金屬和粗糙反射上。0.7～0.9 是實用區間。「只在高光混回」開著時，它和其他滑桿一樣只作用在畫面很亮的地方。
穿透（0.9）玻璃之類看得穿的材質。
自發光（0.5）會發亮的表面——燈條、螢幕。它們閃就往上調。
體積（1.0）霧、煙、光束。體積雜訊通常是整張畫面裡最重的，所以留在 1。細霧絲被抹糊時再往回拉。
混回前濾亮點（開）上面那幾支滑桿把原始雜訊混回來之前，先把裡面孤立的亮點、暗點夾回降噪結果附近的合理範圍。顆粒留著，亮點不會跟著混回來。關掉就跟 1.0.1 的結果完全一樣。詳見下方。
保留顆粒（0.75）原始雜訊可以偏離降噪結果多遠，才會被夾回來。越高保留越多顆粒，也越容易留下亮點。濾亮點關掉時這格會變灰。
先清乾淨引導圖（關）降噪器靠兩張「地圖」認路，這項先把那兩張清乾淨再讓它們指揮。預設關；很暗或很多噪點的鏡頭才開，會讓細小凹凸變柔和。
只在高光混回（開）上面那幾支滑桿只作用在畫面很亮的地方：高光保留層次，其他地方維持乾淨。畫面裡沒有很亮的地方時，滑桿看不出差別是正常的。關掉就作用在整個畫面（舊行為，想要全畫面顆粒感時用）。體積那支滑桿一律作用在整個畫面。
自動用 GPU 跑合成（開）按建立管線時順手把合成器切到 GPU。這棵樹裡塞滿降噪節點，用 CPU 會變慢。
預過濾（精確）那兩張引導圖要清得多仔細。出正片就留在精確。
包含環境背景（開）把世界背景合回畫面。Transparent Film 開著時會自動跳過，免得 HDRI 從透明處漏出來。
套用出片採樣設定先問你一聲，再打開適應性採樣、門檻 0.01、採樣上限用旁邊那格，外加藍雜訊與逐幀換種子。請在跑採樣分析之前按，之後才按套用建議門檻，不要反過來：它一律寫入 0.01，之後再按一次會把門檻改回 0.01。它設的採樣上限也是分析拿來當天花板的值。

另存未降噪畫面（關）額外把完全沒降噪的原始畫面存成 noisy####.exr，放在輸出路徑底下的 noisy image 資料夾，渲一次兩種都拿到。之後想換別的降噪工具試就用得上。這個資料夾是相對 .blend 記的（//<輸出>/noisy image/），另存新檔或整個專案搬家，它都跟著檔案走。檔案要先存過：檔案沒存過、或輸出路徑沒有磁碟機代號時，建立管線會跳過它並跳警告——存檔（或設好輸出路徑）後按重建管線。1.1.0 建過的場景要重建一次，健康檢查會提醒你。

五支滑桿、混回前濾亮點和保留顆粒都是即時的：拖了直接寫進節點樹，不用重建。「改完要重建才生效」那個框裡的全部項目、還有算圖輸出路徑，改完都要再按一次建立管線。建完之後才開或關 Transparent Film，面板會提醒你按重建。這個外掛的設定都不能做動畫——詳見常見問題。

建立時的重要訊息——少了哪個 pass、幫你換了哪個 view layer——會用警告顯示，不會一閃就被後面的訊息蓋掉。

關於建立與移除，還有幾件值得知道的事：

  • 如果 Render Layers 後面緊接一個 Reroute（按 New 時 Blender 產生的預設樹就是這樣），Viewer 接在 Reroute 上，建立之後看到的會是降噪後的圖。想繼續看原始渲染，請把 Viewer 直接接到 Render Layers。
  • 把 Final Quality Pipeline 節點 mute 不等於略過它：Blender 會直接把它的第一個輸入（Diffuse Direct）送出去，畫面會變暗。想比較有沒有 FQP，請按移除，或暫時把 Render Layers 的 Image 直接接到輸出。
  • 輸出原本沒接東西、建立時幫你把鏈尾接上去的話，移除會留著這條線，F12 照樣有畫面。
  • 兩個場景用的是「同一棵」合成樹時，樹裡的管線是共用的。建立時會跳警告；移除會先問你，因為它會把 FQP 從這棵樹上所有場景拿掉。
  • 1.1.0 建的場景，除了接線和 passes 之外沒有記下建立時改了什麼，所以在那種場景按移除，行為跟 1.1.0 一樣。先按移除、再按一次建立管線，之後的移除就會全部還原。
  • 這條管線只在 Cycles 生效，切到 Workbench 時 F12 會整片黑。切換引擎之前請先按 移除；選了別的引擎時，面板仍會留著這顆按鈕，並附一行說明。

混回前濾亮點

那幾支混合滑桿的原理，是把一部分沒降噪的原始畫面混回降噪結果上：自然的顆粒感就是從這裡來的。問題是原始畫面裡也帶著亮點（firefly，那種孤零零、亮得離譜的像素），滑桿拉到 1 以下時，以前會連它們也按比例一起混回來。

混回前濾亮點打開時（預設），每一路原始雜訊在混回之前，會先跟自己的降噪結果比一比。兩者差不多的地方，原始像素原封不動混回去，你選的顆粒感留著；差很多的地方（孤立的亮點，或孤立的暗點），先夾回降噪值附近容許範圍的邊緣再混。容許範圍是 保留顆粒 × 降噪後的亮度，再加一點固定餘量。作用在漫射、高光、穿透、體積四路；自發光照舊。

什麼時候調保留顆粒：

  • 滑桿拉到 1 以下，還是看到白點？往下調。越低越乾淨，顆粒也越少。
  • 拉絲金屬、粗糙反射的顆粒感被收得太乾淨？往上調。越高保留越多顆粒，也越容易留下亮點。
  • 0.75 是不錯的起點。拖了即時生效，不用重建。
  • 滑桿在 1.0 的那一路本來就沒有混回原始雜訊，這個濾鏡在那一路看不出差別。

用舊版建過管線的場景，那條管線裡還沒有這個濾鏡。這時勾選框下面會出現：「按上面的「重建管線」後才能使用」，按一次重建管線就好。把濾鏡關掉，結果跟 1.0.1 完全一樣。

跨幀穩定區

項目作用
跨幀半徑（±1，共 3 幀）前後各拿幾幀來混：±1、±2 或 ±3。越寬越穩，但快速移動會糊，也更花時間。
夾擠寬容度（1.0）鄰幀被信任的程度。調高壓閃爍更狠，但會動的東西可能拖殘影；調低比較嚴格、動態處更乾淨。
深度容許差（0.03）借過來的像素在深度上可以差多少才算數，用「佔離相機距離的比例」表示：0.03 就是 3%。公分級產品照和公里級風景都一樣好用。這是用來擋「上一幀還被遮住的背景」被硬拉進來。1.2.9 起，緊鄰被丟掉像素的那一圈也不採用。調低它清不掉在背景前移動的輪廓（見「已知限制」）。舊版存的絕對值設定（大於 0.3 的）會自動重設成 0.03。
補回動態模糊 + 快門（開、0.5）最後把模糊畫回去。快門值從場景自己的 motion blur 快門帶入，所以結果等於 Cycles 自己會算出來的量。
素材資料夾四組序列寫進去、再讀回來的地方。打 frames/ 這種相對路徑，會當成 //frames/，也就是 .blend 旁邊。從磁碟根目錄開始、卻沒有磁碟機代號的路徑（\frames）會被拒絕。成品資料夾也一樣。

7. 兩支分析器

兩支都會自己開一個主控台視窗，在另一個沒有介面的 Blender 裡跑，你的 Blender 照樣能用。兩支讀的都是磁碟上那份檔案，所以沒存檔會被擋下。兩支分析的都是你眼前這個場景，用的是 Blender 偏好設定裡指定的同一個 GPU 裝置，並把裝置記在報告裡。開跑前先把 viewport 從 Rendered 模式切掉，它佔著分析要用的 VRAM。

光線路徑分析器回答「每條光線要追多遠」，採樣分析器回答「每個像素要算多細」——也就是每一幀的價錢。建議先跑光線路徑那支、套用之後再跑採樣那支。

它會寫出哪些檔

報告寫在 .blend 旁邊，檔名帶著 .blend 的名字，同一個資料夾裡的兩個 .blend 不會共用同一份報告：

檔案內容
<blend>.fqp_lightpath_report.txt / .json光線路徑報告，給人看的／給套用按鈕讀的
<blend>.fqp_sampling_report.txt / .json採樣報告，同樣一對
<報告>.log分析過程印出來的所有東西。出狀況時第一個要打開的檔。
<報告>.status.jsonrunning、ok 或 failed。面板的狀態行就是讀它。

分析還在跑的時候再按一次分析，會被擋下；分析還在跑、或上一次失敗時按套用，也會被擋下——你不會不小心套到上禮拜的數字。套用還會確認報告是這個 .blend、這個場景做的，對不上就拒絕；報告產生之後 .blend 又存過檔，會提醒你。每一顆套用按鈕（套用 Strict、套用 Visual、套用建議門檻）在覆寫任何設定前都會先問你一聲。

用 Render Border 加速

場景有設 Render Border 時，兩支分析器都只量框裡的範圍——通常快 3～10 倍。把框圈在畫面最噪的地方：高光、玻璃、毛髮。

光線路徑分析器的合格線是拿「整張畫面的平均亮度」來比。畫面裡一個小物件配上大片亮背景時，整張可能過關，但物件本身的噪點其實超過合格線。小主角（玻璃、珠寶）請先用 Render Border 框住它再按分析。

有框 border 時，採樣分析器只比框裡的範圍，報告上會註明。

第一張參考圖渲完後，主控台會印出預估的總時間。在那個視窗按 Ctrl+C 可以中止。

參考圖渲出來幾乎整片黑、或有無效像素時，分析會直接停下並說明原因，因為不擋下來的話，黑圖會讓每一項設定看起來都「夠好」。「幾乎整片黑」的意思是：平均低於 0.0001，而且沒有任何像素高於 0.001（linear 數值，螢幕上大約 3/255）。訊息會依序列出可能原因：燈光（關掉、不渲染、或放在被排除的 collection）、曝光或 world 強度，最後才是 GPU。很暗但確實有被照亮物體的鏡頭——太空、夜景——會照常分析。

乾淨啟動

分析器和背景算圖都會另外開一個 Blender。外掛偏好設定裡的乾淨啟動（factory startup）開著時（預設開），那個 Blender 不會載入你裝的其他外掛：啟動比較快、關得乾淨，也不會被某個一開就噴錯的外掛拖下水。

如果場景需要第三方外掛才渲得出來——自訂節點、自訂算圖引擎、住在外掛裡的 driver——就把它關掉。開著的話，這種場景在背景會渲得不一樣，或根本渲不出來。

關掉它有一個要知道的風險：背景的 Blender 會載入你裝的其他外掛。其中如果有外掛註冊了算圖 handler（render_init／render_pre／render_post／render_complete），而場景又讓顯示卡記憶體溢出，光線路徑分析可能停住不動。量到的是：有這類 handler 且溢出，3 次裡 3 次停住；沒有 handler 且溢出，5 次裡 0 次。樣本很少，是哪一個 handler、機制是什麼沒有查；乾淨啟動關著的這條路本身也沒有實測。分析時偵測到 render handler，報告的 Notes 會多一段提示。用不到第三方外掛的場景，保持乾淨啟動開著。

光線路徑分析器

它先渲一張「全部開到最高」的標準答案，再一項一項往下調著渲、跟它比。因為每一張都用同一組亂數，雜訊顆粒在所有圖上長得一模一樣，比對時會自己抵銷——這就是為什麼測試圖可以又小又便宜。按下分析光線路徑之後，通常會算 15 到 45 張小測試圖，實際張數寫在報告裡。

為什麼要量。 Blender 的出廠值是 Diffuse 4／Glossy 4／Transmission 12／Transparent 8／Volume 0。下面兩個是量到的例子，各自只代表那一個場景，不是通則：一朵雲的場景，Volume 的出廠值是 0，這個場景量到 48 才收斂——32 那一階對參考圖的色差 dE p99 是 4.075，48 那一階是 0.033（門檻 0.360）。一個樹葉場景，Transparent 的出廠值是 8，量到的 Visual 值是 16（Strict 24）。

它替每一種光路（Diffuse／Glossy／Transmission／Transparent／Volume）找兩個值。報告裡各有一組，面板上各有一顆套用按鈕：

  • Strict：未降噪的圖對參考圖的誤差（rel.RMSE 與 tm.RMSE），兩個指標都要低於門檻 0.0020（0.20%）。rel.RMSE 是純數學誤差；tm.RMSE 先模擬人眼對暗部的敏感度再比。線性空間的誤差會被畫面亮的部分主導，只出現在陰影裡的差異容易被蓋過去，所以兩個指標都要過。
  • Visual：OIDN 降噪後、顯示出來的圖對參考圖的色差（dE2000，先模糊 1 px），兩項門檻都要低於：dE p99 0.360、dE>2 的像素比例 0.100%。它代表的意思是：與參考圖來回切換時，差異很小、小到不在意。

兩者量的東西不同，所以同一組值可能通過其中一個、沒通過另一個。

Visual 那兩項門檻是校準來的，條件照實列在這裡：一位受過訓練的觀察者、靜態圖、對最高設定來回切換，取他判斷「從這一格起差異小到不在意」的那一格（2026-10-04；標記時看得到格數，不是盲測）。同一位觀察者同一天另做了一輪盲測：82 個試次，其中 12 個是兩張相同的對照題，被答成「兩張不同」的是 0 個。動畫不在這次校準的範圍內：逐幀之間的變化沒有量。Visual 的適用範圍就是這些條件：一位觀察者、靜態圖。

怎麼量、量到哪裡。

  • 從你的設定往上量。你場景用的值高於某個通道的梯頂時，階梯會加長到那個值，對的參考值至少是它的兩倍（最高 128）。
  • 掃到梯頂還沒收斂的通道，會把參考值加倍、重算一張參考圖，再往上多量幾階——最多 2 輪，參考值不超過 128。被測值一定不超過參考值的一半（否則量到的會是自己、誤差假性歸零），所以 64 是量得到的最高值。仍不收斂就標成 NOT converged。
  • 沒收斂的通道，報告會說接下來可以怎麼做（措辭依情況不同）。量到的最高值還不到 64 時，動作都一樣：把場景裡這一項的值調高再分析一次，分析器會量到你的設定為止，最高量到 64（對參考 128）。高於 64 的值請用眼睛判斷。
  • 連續兩階都在門檻內，這一梯就停下，剩下的階不算；報告會寫出沒算的是哪幾階。
  • 這一幀沒有用到的光路——反彈 0 次的那張圖對參考圖的兩個誤差都在 1e-05 以內——只算那一張。有體積的場景會先用一張圖一起檢查 Diffuse、Glossy、Transmission、Transparent 四項。
  • 沒偵測到 volume（world／材質的 Volume 都沒接，也沒有 Volume 物件）時，volume 那一梯整個跳過，Volume 維持原值不動。
  • 分析用的小圖把貼圖限制在 1K（1024 px）。只限這次分析，場景沒有改動，正式算圖用的仍是場景原本的貼圖設定。面板上沒有這個開關。

兩組值都會合起來再驗一次。 每一項是單獨量的；合起來會不會互相加成，只有一起渲才知道。

  • Strict 聯合驗證：把 Strict 這一組值一起套上實際渲一張。高於門檻時，還有更高一階的通道各升一階、再整組算一張；這一組通過就採用它（ESCALATED）。升階後仍沒過時結果是 FAILED：誤差（tm.RMSE）下降不到 10% 的話升階不採用，報告列的是第一組。已經在上限、無法再升的是哪幾項，報告會寫出來。
  • Visual 整組驗證：把各通道各自的 Visual 值一起套上算一張，量降噪後的色差。沒通過時，所有低於 Strict 值的通道一起升一階再算一張；升階後仍沒通過，這份報告的 Visual 值就是 Strict 值。Visual 設定與 Strict 設定相同時不另外算。

「一起升一階」這條規則對照過一位觀察者（作者）在五個場景設定上的判斷：四個相同，一個（廚房場景的酒瓶鏡位）外掛比他多升一階，沒有比他鬆的。

沒把握就不調低你的設定。

  • Strict 在量測範圍內沒有收斂的通道（報告標「量到的最高值，未收斂」）：你的設定比較高時保留你的設定。Visual 不另外給值，沿用 Strict 的值。
  • Strict 只在梯頂一階達標、上面沒有可以確認的階的通道（報告標「只在梯頂一階達標，未確認」）：Visual 同樣沿用 Strict 的值。
  • 這一幀沒有用到的光路，以及沒偵測到煙霧或霧氣時的 Volume：維持你原本的設定，不寫入。
  • Max Bounces 不會被調低。寫入的各值總和高於你現在的 Max Bounces 時才改成那個總和。

兩顆套用按鈕。 套用 Strict 把 Strict 那一組填進 Render Properties > Light Paths，套用 Visual 填 Visual 那一組。按鈕上括號裡的數字是套用後的 Max Bounces，例如「套用 Strict (116)」；滑鼠停在按鈕上會列出各通道的值。兩顆按鈕在寫入前都會先問一聲。報告沒有 Visual 結果時，套用 Visual 不能按，面板會寫「這份報告沒有 Visual 結果——請重新分析」。

實測的例子（廚房場景、酒瓶鏡位）：場景原本是 Diffuse 32／Glossy 64／Transmission 32／Transparent 16／Max Bounces 112。套用 Strict 之後是 24／64／24／4／Max Bounces 116；套用 Visual 之後是 12／64／24／4／Max Bounces 112。

看報告在畫面上跳重點：列的是按套用會寫入的值（不是量到的膝點）、兩種整組驗證的結果、要注意的項目。逐階數字印在主控台，也存成 <blend>.fqp_lightpath_report.txt。

自己寫程式讀 .json 的人：請讀結構欄位（數值與狀態）。裡面的說明文字（visual_note、verification.note、verification.reference_note 等）會隨措辭與語言改變，不保證穩定。

Strict 聯合驗證沒過時。 報告最後會多一段，列出要手動調高的項目，每一行列的是「套用 Strict」會寫入的值。一般經驗（不是這次量到的）：這在玻璃、金屬、鏡面多的場景很常見——光在裡面反覆反射，要很多次才走完。經驗法則（不是量測）：加完再看一次畫面，玻璃後面、反射裡的東西如果不再偏暗，就可以了。64 是分析器量得到的最高值；超過它的值請用眼睛判斷。

還有一個值得知道的細節：建議值出現 0 會被單獨標出來。那對「現在的場景」是對的，但你之後加了會用到那條光路的材質（例如透明貼圖的樹葉）就不對了。

採樣分析器

它先渲一張「採樣開很高、完全不設門檻」的標準答案，再用一組由鬆到緊的門檻各渲一張（一定包含最緊的 0.002），每一張都計時。

關鍵的設計決定：每一張都先降噪過，比的是完成的畫面。拿沒降噪的原圖來量是套套邏輯——適應性採樣留下的殘噪本來就差不多等於門檻自己，那等於拿門檻量門檻。而且你最後看的本來就是降噪後的畫面。

每一階都拿去跟最緊的那一階比。建議值是「成品與最緊一階相差 10% 以內」的最便宜一階——純數學誤差和模擬人眼看暗部的誤差都要在 10% 以內。這支的梯子方向跟光線路徑那支相反（由鬆到緊），所以是從最緊那端往鬆走，遇到第一個差超過 10% 的階就停；鬆端某一階運氣好也搶不走。報告的寫法是「建議 Noise Threshold X：在本次分析中，成品誤差與最緊一階（0.002）相差 Y% 以內」。

25% 的小圖可能漏看高光，所以小圖選到比最緊一階鬆的階時，會再用 50% 跑一輪，取兩者較緊的那一個。場景真的需要最緊一階時，報告會寫「這個場景需要最緊一階（暗部或高光還在變）」，套用建議門檻填的就是這一階。

最緊的兩階（0.005 與 0.002）成品幾乎一樣——最後一輪兩個誤差都相差 0.1% 以內——代表兩階都被 Max Samples 卡住，報告和套用時都會多一行提示（WARNING）。選到最緊一階時，提示寫：限制這個場景的多半是 Max Samples；若仍嫌噪，可提高 Max Samples 後重新分析。選到較鬆一階時，提示寫：較緊的幾檔被 Max Samples 上限卡住、成品幾乎一樣，所以選了這一檔；想要更乾淨請調高 Max Samples 後重新分析。選「首中尾三幀」（見下）時，三幀任一幀撞到就會提示，並列出是哪幾幀。這個提示不會改變選擇。

分析時一律用 CPU 降噪、關掉 persistent data，同一個場景每次都得到同一個答案；你的設定在分析結束後都會還原，中途出錯也一樣。

限制：分析時不渲動態模糊，動態模糊鏡頭的結果不含它；攝影機開景深時會自動再收緊一檔（報告與 Info 那行會寫出分析原本建議的那一階）；自訂鏡頭（例如 OSL 鏡頭外掛）的景深 Analyzer 無法判斷，請自行評估。另外，分析目前這一幀約需 10～50 秒；同一鏡頭分析一次即可一直沿用。算動畫請改選下面的「首中尾三幀」。

分析幀數（在「分析採樣門檻」按鈕正上方）決定分析要看哪幾幀。預設的目前這一幀 只分析場景現在停的那一幀，做法就是上面講的那樣。首中尾三幀用同樣的步驟分析幀範圍的首、中、尾三幀（1～48 就是 1、25、48），取其中最嚴的選擇；景深那一步放在這之後，三幀裡任一幀攝影機開了景深就收緊一檔。報告會逐幀列出各幀的選擇，並寫明決定結果的是哪一幀，「相差 Y% 以內」用的是那一幀的數字。算動畫時建議選它：只看一幀可能選到比整個鏡頭需要的還鬆的階——暗的一段撞到 Max Samples，看起來 0.02 就夠，亮的一段卻需要 0.01。面板在這個選項旁邊也會提醒。限制：分析時間約 3 倍（約 30～150 秒），目的是避免選錯，不一定省時；亮段很短且不在這三幀時仍可能漏掉；未烘焙的模擬在跳幀分析時可能與實際渲染不同，請先烘焙。幀範圍只有一幀時，效果等同「目前這一幀」。

套用建議門檻只設 adaptive_threshold。Max Samples 刻意不動：這次分析就是拿你現在的值當天花板量出來的。

8. 背景算圖

背景渲這一幀和背景渲整段動畫會把工作交給第二個沒有介面的 Blender，它自己開一個主控台視窗。介面完全不佔 VRAM、照樣能用，你甚至可以把它關掉——算圖會自己跑完。

那個視窗會即時報：

[FQP] 幀 12/240 完成 | 這幀 41.3s | 平均 39.8s/幀 | 剩 228 幀 ~= 2 小時 31 分 | 預計 18:42 完成

第一幀渲完就開始估，之後一直用「到目前為止的平均」重算，所以場景後半變重會自己反映出來。「這幀幾秒」用的是 Blender 自己印的 Time:，不含開檔載場景的時間——這就是為什麼第一次的估算就能用。總幀數會照你的 Frame Step 算。

Blender 原本的輸出一行不少地照印在下面。全部跑完會給你總幀數、總耗時、最快與最慢的一幀，還有 Blender 的結束代碼。

兩個提醒：它渲的是磁碟上那份，所以先存檔；還有 GPU 一次只夠一個算圖用，所以別又去按 F12。

Overwrite 關著（Output Properties > Output）接著續渲動畫時：總幀數和預計完成時間只算還要渲的幀，視窗也會說跳過了幾張已經存在的幀。

萬一機器上找不到 python，進度摘要會停用，按鈕就退回直接開 Blender。算圖本身完全不受影響。

給自己手動啟動分析器或監看器腳本的人：參數必須是 JSON 物件，數字要寫成數字（寫 16，不要寫 "16"）。不符合的話，工作會以「失敗」結束，並用一句話說明哪裡不對。

9. 動畫出片完整流程

渲之前

  1. 引擎設成 Cycles、指定一顆相機、存檔。
  2. 建立管線 → 套用出片採樣設定 → 設成 32-bit EXR 輸出。
  3. 把動態模糊關掉。Frame Step 留在 1。
  4. 選好 Beauty 來源，按準備動畫素材輸出。
  5. 按健康檢查，把每一行讀完。

渲 —— 只做一次，而且這是最花錢的一段。Ctrl+F12，或用背景渲整段動畫那顆。

渲完之後 —— 很便宜，想重試幾次都行：

  1. 建立跨幀場景 → 執行跨幀穩定。
  2. 看成品。會動的東西後面拖殘影，代表夾擠寬容度太高或半徑太寬；還在浮動就相反。改完再跑一次——完全不用重渲。跨幀穩定在鎖定機位或慢速鏡頭效果最好；快速推軌或橫移時，也要看在背景前移動的物體輪廓，它可能比不開跨幀穩定稍差（見「已知限制」）。

幀範圍是看磁碟上真的有哪些檔案決定的，不是看場景的幀範圍；序列中間有破洞會直接停下，而不是默默渲出一批讀錯鄰幀的成品。破洞間隔一致時，訊息會提醒你看 Frame Step、或命令列的 -j 參數。從第 0 幀開始的序列，第 1 幀也會被穩定化。落在準備範圍之外、或比最後一次準備還舊的幀，會被當成殘留幀報出來，不會被混進去。

Placeholders 開著、Overwrite 關著（Output Properties > Output）時，中斷再續渲會留下 0 byte 的檔，續渲時會跳過那些幀。執行跨幀穩定會停下並點名它們：把 0 byte 的檔刪掉（素材資料夾和你的 Output 資料夾都要），再把那幾幀重渲。動畫的話，關掉 Placeholders、或打開 Overwrite 會比較省事。

補渲幾幀

跨幀穩定跑完了，結果有幾幀要重渲——或有幾幀缺了？不用整段重渲。

  1. 修好場景。幀範圍維持按準備時的範圍，Frame Step 留在 1。
  2. 按準備（保留已算好的幀）（在準備動畫素材輸出下方；素材資料夾裡有這個場景、同一段幀範圍的準備紀錄時才會出現）。狀態列會說保留了幾幀、還缺哪幾幀。
  3. 只渲需要的幀：把 Frame Start／End 設成那幾幀，用 Render Animation 渲（單張 F12 不會寫出帶幀號的素材）。重渲的幀會取代舊檔。渲完把幀範圍改回來。
  4. 按執行跨幀穩定。所有檢查照做——0 byte、尺寸不同、壞掉的檔一樣會擋下。

保留下來的幀不會檢查是否過期。渲完之後改過場景、燈光、材質或渲染設定的話，請用一般的準備動畫素材輸出，整段重渲。幀範圍不同、Frame Step 不是 1、或資料夾是別的場景準備的，這顆按鈕會拒絕並說明原因。另外兩件事：一般的準備按完、還沒開始渲之前，這顆按鈕就會出現——這時按下去會把舊幀全部保留，確定它們還能用才按；不同資料夾裡同檔名的 .blend 會被當成同一個檔，共用同一個素材資料夾時可以互相補渲。

10. 常見問題

合成變得好慢。 這棵樹裡有很多降噪節點。先確認合成器跑在 GPU 上（健康檢查會報）。「先清乾淨引導圖」預設關；如果你為了很暗、噪點很多的鏡頭把它打開，會多兩顆降噪節點。

準備動畫素材輸出按不下去，說要我關動態模糊。 動態模糊開著的時候 Cycles 不輸出 Vector pass，而跨幀那一段的對齊完全靠它。你不會少掉任何東西：模糊最後由 Vector Blur 補回來，快門值直接用場景自己的設定。

動畫成品頭尾少了幾幀。 故意的。頭尾那幾幀有一邊沒有鄰居，沒有東西可以拿來穩定它們。兩端各多渲幾幀當緩衝就好。

穩定後會動的東西拖著殘影。 把夾擠寬容度調低、或半徑縮小、或深度容許差調低。有殘影就代表鄰幀被信任得超過它應得的程度。在背景前移動的物體輪廓上出現一列細細的點（快速推軌或橫移）是另一回事：跨幀穩定在鎖定機位或慢速鏡頭效果最好，上面這些設定修不掉它。那一段改用逐幀的結果（見「已知限制」）。

可以用 EEVEE 嗎？ 不行。這條管線吃的是只有 Cycles 才生得出來的 per-pass 與 denoising 資料。

我建完樹之後才加 Glare，重建會不會弄丟？ 不會。建立管線會把你整條濾鏡鏈走完，然後把自己插在最前頭；鏈尾如果沒接到 Group Output，它會幫你接上（移除時這條線會留著）。吃算圖原圖的平行分支——例如把 Glare 疊回原圖的那種——也會一併改吃降噪後的圖，不會有哪條分支偷偷把有雜訊的原圖帶回來。

Transparent Film 有什麼要注意的？ 它開著的時候「包含環境背景」會自動跳過，面板上會寫。不然 HDRI 會從透明的地方漏回來。建完之後才改 Transparent Film，要按一次重建——面板會提醒你。跨幀那一段會把透明通道一路保留到成品。

一個 .blend 裡有好幾個 scene？ 每個場景都有自己的節點群組——用 Full Copy 或 Linked Copy 複製出來的場景，第一次在那裡動滑桿時也會拿到自己的一份。但兩個場景如果指向「同一棵」合成樹，樹裡的東西（包括 FQP）就是共用的。遇到這種情況，建立管線和健康檢查都會告訴你；想讓兩邊各自設定，請給其中一個場景一棵自己的合成樹（Compositor 標題列的節點樹選單），再在那裡按建立管線。想讓副本回到共用，Undo 也會把分家一起復原。

有好幾個 view layer？ 建立管線會用「接到最終輸出」的那顆 Render Layers 節點，並讓它讀你目前所在的 view layer（那一層不會被渲染的話，改讀第一個會渲染的）。按移除會切回來。

Render Layers 讀的是別的場景，或一個合成裡有好幾個 layer？ FQP 只處理「按建立管線的那個場景」。Render Layers 節點讀別的場景（跨場景合成）不支援：請在實際渲染的場景裡建立管線，再到合成用的場景疊它的結果。每個場景只會對一個 view layer 降噪；要合成多個 layer，請讓每個 layer 各自用一個場景。

滑桿可以做動畫嗎？ 不行。FQP 的滑桿與各項設定都不能做動畫：它們的值存在合成節點裡，或在你按按鈕時才讀取，算圖時不會重讀。右鍵不會出現 Insert Keyframe；想在鏡頭中途換樣子，請分段算。舊檔若在這些設定上留有 keyframe，不會生效，健康檢查會列出來。到 Dope Sheet 或 Graph Editor 把它們刪掉，再把那幾個設定各動一次，面板和節點才會一致。

Shadow Catcher 呢？ Shadow Catcher 必須搭配透明背景。背景不透明時，FQP 是用光 pass 重組畫面，接住的影子會消失；請打開 Film > Transparent，再疊到你的背景底片上。遇到這種情況，建立管線和健康檢查都會跳警告。

我的 Group Output 有好幾個輸入。 Blender 算圖只用作用中那顆 Group Output 的第一個輸入，所以 FQP 也只接、只讀第一個。

重按準備之後，執行跨幀穩定把我所有的幀都當成殘留幀。 準備代表開始新的一輪，在它之前渲的幀就算殘留。那些幀如果還能用，請改按 準備（保留已算好的幀），只補渲缺的——見補渲幾幀。

把反彈調高，要多花多少算圖時間？ 光線路徑報告會給一個從 25% 小測試圖反推的粗略級距（讀法見光線路徑分析器）；正式算圖的時間它沒有量。下面是另外在幾個場景量到的數字，不是保證（RTX 4090）。表面的反彈（Diffuse／Glossy／Transmission／Transparent），量到的增加幅度如下：把反彈全部開到最高、對 Blender 出廠值比，廚房場景最多慢約 9–11%（兩份量測的最大值是 +11.3% 與 +9.07%），樹葉場景最多約 6%（+5.6%）。體積的反彈影響很大：一朵雲的場景（640×960、256 samples），Volume 0／16／32／64 分別是 30／183／216／215 秒。

雲或煙的 Volume 反彈要設多少？ 讓分析器量。Blender 的出廠值是 0。量到的例子（只代表這一個場景）：一朵雲的場景原本設 32，Strict 與 Visual 的值都是 48——32 那一階對參考圖的色差 dE p99 是 4.075，48 那一階是 0.033（門檻 0.360）。濃密的雲可能算很久，另見健康檢查的體積提示。

有透明貼圖的樹葉，Transparent 要設多少？ 讓分析器量。Blender 的出廠值是 8。量到的例子（只代表這一個場景）：一個樹葉場景，Diffuse／Glossy／Transmission 的 Visual 值是 1／1／2（Strict 3／2／4），Transparent 是 16（Strict 24）——這條光路需要的值比其他幾項高很多。

改壞了想回去？ 按移除就會還原你原本的合成器接線，以及它打開過的 passes，並把建立時改過的其他東西（它新建的樹、補上的節點、Compositing 與合成器裝置）改回來；移除動畫輸出節點對跨幀那顆節點做一樣的事。除了合成器、render passes、Light Paths 和採樣設定以外，它什麼都不碰；而後面那兩項也只有在你按下明講會改它們的按鈕時才會變——那些按鈕都會先問你一聲。

11. 各平台行為差異

Windows 會為每個背景工作開一個真正的主控台視窗。macOS 用 osascript 請 Terminal.app 開。Linux 依序找 x-terminal-emulator、gnome-terminal、konsole、xterm，用第一個找得到的。

開不了終端機時——機器上沒裝，或 macOS 不允許 Blender 控制 Terminal——工作照跑：它會脫離父行程到背景執行，輸出寫進 .blend 旁邊的 log 檔（分析器寫 <報告>.log，背景算圖寫帶時間戳的 fqp_<工作>_<時間>.log）。警告訊息會把路徑講出來，用文字編輯器開，或 tail -f 它。

測試狀態：

  • Windows——真機測試過；平常實際拿來幹活的就是這個平台。
  • macOS——作者已在真機測試過（MacBook Pro M1，2026-10-07），沒有發現問題。
  • Linux——有測試套件涵蓋，尚未在真機上測過。

12. 已知限制

  • 只支援 Cycles。 這不是偏好，是相依。
  • 跨幀那一段需要連續幀。 Frame Step 大於 1 產生的序列它用不了，而且它會直接說，不會自己亂猜。
  • 跨幀穩定在鎖定機位或慢速鏡頭效果最好。 快速推軌或橫移時，在背景前移動的物體輪廓可能比不開跨幀穩定稍差，有時是一列細細的點：深度檢查是逐像素的，而反鋸齒的輪廓像素一部分是物體、一部分是背景。整段開渲前先檢查會動的輪廓；輪廓比閃爍更要緊的那一段，改用逐幀的結果（素材資料夾裡的 beauty####.exr）。
  • 物體自轉、燈光不動的鏡頭，跨幀穩定可能比逐幀降噪差。 例如轉台上的產品。這是另一個研究（跨幀降噪）量到的，條件照抄：扭蛋機場景，相機固定，機台每幀自轉 7°，燈光固定；16 samples、adaptive 關、animated seed 開、960×480、32 幀，評估第 4–29 幀；參考圖每幀 2×2048 samples。量到的數字（越小越好；tonemap 空間 ×1000），前者是 Cycles 內建 OIDN 逐幀、後者是 FQP 1.2.9 加執行跨幀穩定：逐像素時間誤差（閃爍）全圖 2.03 對 2.75；邊緣區時間誤差 21.3 對 29.5；對參考圖的誤差（tm-RMSE）全圖 5.72 對 7.97。這是單一場景、16 samples 的量測，不是普遍結論。同一批測試裡，室內的快速橫搖與推軌鏡頭上，執行跨幀穩定是贏逐幀的：全圖的時間誤差，同樣逐幀在前、跨幀穩定在後，橫搖鏡頭 19.62 對 17.71，推軌鏡頭 15.73 對 14.79。這類鏡頭整段開渲前，先拿幾幀，把跨幀穩定的結果與不做跨幀穩定的結果並排比過再決定。上面的數字比的是 Cycles 內建降噪的逐幀結果，不是 FQP 自己的逐幀結果。
  • 兩支分析器要先花一點時間。 同一鏡頭分析一次即可一直沿用，所以在一整段序列、或一個會反覆重渲的場景上最划得來。
  • 採樣分析器量的是代理。 它用 Cycles 內建的降噪器代替這條管線的 per-pass 降噪，兩者的偏差方向不固定。分析時不渲動態模糊，攝影機開景深時會自動再收緊一檔（自訂鏡頭例如 OSL 鏡頭外掛的景深無法判斷，請自行評估）；景深、動態模糊或毛髮較重的場景，可能要比報告再收緊一檔——整段序列開渲前先檢查一幀。
  • 光線路徑分析器只量一個鏡頭的一幀；採樣分析器在預設的「目前這一幀」也一樣。 動畫裡反射和打光會變，換鏡頭的時候多留一階的餘裕很便宜；或把「分析幀數」改成「首中尾三幀」，看幀範圍的首、中、尾三幀（亮段很短、落在三幀之間時仍可能漏掉）。
  • Visual 只以一位觀察者、靜態圖校準。 動畫裡逐幀之間的變化沒有量；其他觀察者、並排或單張觀看也沒有量。
  • 暗場景的 Strict 可能差一兩格。 Strict 的誤差是除以整張圖的平均亮度算的，畫面很暗時，一個像素就可能決定結果。量到的例子：一個暗巷場景（貼圖限制 1K），只換 seed（算圖用的亂數起點；分析固定用 seed 0），Diffuse 第一個低於門檻的階在 seed 0／1／2 分別是 12／8／6，差異來自單一個像素。另一個例子：同一份程式重跑暗版的廚房場景，Glossy 梯頂那一階的 tm.RMSE 有一次差了 8.4e-4（門檻 0.002 的 42%），判定沒有變。1.3 沒有改 Strict 的量法。這一條說的是同一個 Blender 版本重跑；換了版本不在此限，見下面「換 Blender 版本」那一條——那裡有一個暗場景，兩個版本連 Strict 的結論都不同。
  • Visual 的數字每次重跑有小幅浮動。 分析時的降噪用 GPU。量到的：暗版廚房場景的酒瓶鏡位，同一組設定（Diffuse 8／Glossy 64／Transmission 12／Transparent 4）的整組驗證跑了兩次，dE p99 是 0.2970 與 0.2866，相差約 0.01（門檻 0.360，兩次都通過）。GPU 降噪對 CPU 降噪，在靠近門檻的整組回合相差 0.0001–0.0044，那幾組對照的判定沒有因此不同。
  • 換 Blender 版本，結果可能不同：多半是差一階，暗的場景可能連 Strict 的結論都不同。 下面是八個場景設定在 Blender 5.1.2 與 5.2.1 各跑一次的結果，不是保證。
    • 樹葉、一朵雲、扭蛋機：兩個版本的判定與建議值都相同。暗版廚房的酒瓶鏡位：判定與套用的值兩版相同。
    • 廚房、暗巷：有通道差一階。廚房酒瓶鏡位的 Transparent 是 4（5.1.2）對 8（5.2.1）。廚房的另一個鏡位（全景），Diffuse 膝點（Strict）是 24 對 16，Visual 值有三個通道各低一階（Diffuse 12 對 8、Transmission 12 對 8、Transparent 8 對 4）。暗巷的 Diffuse 是 8（5.1.2）對 12（5.2.1）。
    • 暗版廚房的全景鏡位：5.1.2 的 Glossy 只在梯頂一階達標（算收斂，未確認），Strict 聯合驗證升一階後通過；5.2.1 把同一個通道判為未收斂，Strict 聯合驗證升階後仍沒過、升階不採用。套用 Strict 會寫入的值因此不同（Diffuse／Glossy／Transmission／Transparent：32／64／24／8 對 24／64／16／4）。在這個場景，兩個版本的 Visual 值相同（8／64／6／4）。

    這與上面「暗場景的 Strict」那一條是同一類現象（原因沒有另外量）。所以在一個版本看到「未收斂」加上「Strict 聯合驗證沒過」、另一個版本卻沒有，是已知的行為，不是工具壞了：報告對沒把握的通道不會調到比你的設定低，要手動調高哪幾項列在報告最後一段（見光線路徑分析器的「Strict 聯合驗證沒過時」）。建議：換了 Blender 版本就重新分析，不要沿用另一個版本的報告。

  • 貼圖限制 1K 的依據只有三個場景。 扭蛋機、廚房、樹葉三個場景，在不限制／2048／1024／512 四種設定下判定全部相同。受益的是顯示卡記憶體裝不下的場景：一個 2.5 GB 的暗巷場景，整個分析在 1.2.9 是 1273 秒，1.3 開發期間量到 239 秒與 181 秒（RTX 4090）。本來就裝得下的場景不會因此變快；1K 限制下仍然裝不下的場景，目前沒有答案。
  • 顯示卡記憶體溢出時，分析仍會跑，但變慢。 量到的例子：同一個暗巷場景不限制貼圖時每張測試圖 16–26 秒，限制 1K 時每張 3.8–4.0 秒。1.3 沒有另外處理溢出的情況。
  • 分析要多久，下面是量到的數字，不是保證（RTX 4090）：樹葉場景約 10 秒、廚房約 85 秒、暗巷（2.5 GB）約 181 秒、一朵雲約 400 秒。主控台印的預估時間是粗估，最後一次預估對實際秒數：樹葉 9.7 對 10.1、廚房 83 對 85、暗巷 180 對 181、雲 339 對 400（低 15%）。
  • 乾淨啟動關著時，光線路徑分析有停住的風險——見乾淨啟動。
  • 面板很窄時，兩顆套用按鈕的字會被縮短。 Blender 會把按鈕文字縮成「套用 Stric...」（英文介面是「Apply Str...」），括號裡的數字就看不到了。量到的：Properties 編輯器寬 339 px 時文字完整，寬 225 px 時被縮短。把 Properties 編輯器拉寬，或把滑鼠停在按鈕上看 tooltip。
  • 彈出視窗裡過長的行會自動折成多行，但仍有折不到的情況。 健康檢查、光線路徑的「看報告」、「看採樣報告」這三個彈出視窗都一樣：過長的行折成多行，續行比原行多往內縮一點；系統主控台與報告檔的內容保持原樣、不折。仍然成立的限制：視窗很窄、或介面縮放（Resolution Scale）很大時，行尾仍可能被切掉；彈出視窗比 Blender 視窗還高時，Blender 會顯示捲動箭頭。完整內容永遠在系統主控台（Window > Toggle System Console）；兩支分析器的報告另有報告檔。
  • 背景工作讀的是磁碟上的檔案。 你還沒存的修改它們看不到，這也是為什麼檔案是髒的時候它們會拒絕啟動。
  • 一個場景、一個 view layer。 不支援跨場景合成，每個場景也只會對一個 view layer 降噪——見常見問題。
  • Shadow Catcher 必須搭配透明背景。 背景不透明時，接住的影子會消失。
  • 設定不能做動畫。 鏡頭中途要換樣子，請分段算。
  • 執行跨幀穩定的檔案檢查有極限。 大小正常但內容壞掉的 pass 檔、或只被截掉一點點的檔，抓不到。多 part 的 EXR——Blender 5.1 寫出的 multilayer EXR 就是——會跳過解析度檢查並跳警告。FQP 自己寫的檔是單層的，一定會被檢查。
  • 保留下來的幀是被信任的。 準備（保留已算好的幀）不會檢查保留的幀是否過期。
  • 全黑檢查看的是算圖結果本身。 Color Management 的 view Exposure 沒有算進去，所以只靠很大的 view Exposure 撐亮的場景會被當成全黑拒絕——請改用燈光或 Film exposure 調亮。參考圖採樣數極低（1，只有自己手寫分析器參數時才可能；面板一律用 2048）時，全黑場景可能不會被拒絕。

14. 與其他降噪外掛共存

同時開著兩套合成器降噪，效果會疊加：畫面被降噪兩次，細節被抹掉。一個場景挑一套就好。

這個外掛只在你按建立管線（或移除）的時候改合成器。它不會在背景跑任何東西，開檔時也不會碰合成器。如果你建好之後，別的外掛又重建了合成器，健康檢查第 9 項會告訴你，再按一次建立管線就會把它插回最前面。

建立管線不會去找你自己鏈上原本就有的 Denoise 節點。如果有，請自己把它 mute 或刪掉。

15. 解除安裝

  1. 在每個建過管線的場景按 移除（用過跨幀流程的話，也按 移除動畫輸出節點），然後存檔。
  2. Edit > Preferences > Add-ons（或 Get Extensions），把它的勾拿掉。
  3. 展開它那一列，移除／解除安裝。

沒清理過的檔案也沒關係。管線本身就是一般的 Blender 合成節點，所以那種檔案沒有這個外掛也照樣能開、照樣能渲——只是滑桿不再是即時的。建過的 FQP_Temporal 輔助場景會留在檔案裡，不要的話從場景選單刪掉就好。
